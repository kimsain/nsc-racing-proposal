# NESCL R 제안 사이트는 표 문서 대신 한 화면에 주장 하나씩 넘기는 9장면 설득 페이지로 다시 만듭니다

## 1. 결론

지금 사이트는 표 8개 가까이를 이어 붙인 보고서처럼 읽혀서, FGI 5분 안에 무엇을 하자는 제안인지 전달되지 않습니다. 새 사이트는 9장면으로 갑니다. 순서는 문제, 선례, 투트랙 제안, 타이다잉 정체성 안심, 숫자가 있는 상세페이지, 라인업, 실행 단계, 질문입니다. 장면마다 제목 한 문장이 곧 주장입니다.

화면 부품은 **스펙 라벨** 하나로 통일합니다. 영양성분표처럼 굵은 줄로 위계를 만들고, S2, S6, S8에 같은 모양으로 반복합니다. 빌드 없는 정적 HTML은 그대로 두고 폰트는 Pretendard 하나로 바꿉니다. 숫자는 data.js 한 곳에만 둡니다. Codex로 새로 그리는 사진은 4장 안팎이고, 톤이 맞는 기존 제품컷은 다시 씁니다.

심사위원 세 명 모두 이 뼈대(9장면 설득 스크롤)를 1등으로 골랐습니다. 지적받은 결함 다섯 가지는 아래 계획 안에서 고쳤습니다.

## 2. 지금 사이트에서 마음에 안 드는 지점

- **첫 화면이 답부터 꺼냅니다.** 히어로에 95 g/m²와 여섯 칸짜리 스펙 플레이트(CFM, MVTR, RET, CLO, 무게, 기온)가 ASTM D737 같은 규격 코드와 함께 나옵니다. 95가 왜 중요한지는 04 라인업에 가서야 설명합니다. 그래서 처음 보는 담당자에게는 용어만 보입니다.
- **표 모음처럼 읽힙니다.** 본문 표가 why, tracks, xfer, gloss, compare, 레이어링 결과까지 6개이고, 상세 dialog 안에 2개가 더 있습니다. 섹션 01~08이 모두 번호, 명사구 제목, 회색 소개 문단, 표 순서의 같은 틀이라 어디가 핵심인지 구분되지 않습니다. 주장은 작은 회색 문단에 묻혀 있습니다.
- **설득 순서가 거꾸로입니다.** 용어표(03)가 제품(04)보다 먼저 나옵니다. 가장 강한 카드인 07 STEP 0(첫 단계는 돈이 거의 들지 않는다)은 계산기 뒤에 있고, 근거가 되는 해외 사례(08)는 맨 끝에 있습니다. 마지막에 대화를 이어 갈 질문도 없습니다.
- **같은 숫자가 네다섯 곳에 따로 적혀 있고, 서로 어긋나기까지 합니다.**
  - Singlet 95의 190 CFM이 히어로, why 표, 카드, PRODUCTS.kpis, COMPARE_ROWS에 각각 하드코딩돼 있습니다.
  - R-01 설명에는 "레이스 강도에서는 8°C부터"라고 적혀 있습니다. 그런데 recommend(8°C, 3 m/s, 레이스)를 돌리면 운동 시 체감이 15°C로 나오고, 추천은 Singlet 95가 아니라 기능성 반팔과 Half Tights 210입니다. 심사 과정에서 직접 실행해 확인한 결과입니다.
- **폰트와 라벨이 지침과 맞지 않습니다.** styles.css가 Switzer, Fragment Mono, Pretendard를 섞어 쓰고, KEY NUMBERS나 SPECIFICATION 같은 영문 대문자 라벨이 한국어 본문과 부딪힙니다. 본문 15px, 라벨 11~12px이라 화면 공유로는 읽히지 않습니다.

## 4. 시각 체계

- **색.**
  - 배경은 사진 배경과 맞춘 따뜻한 밝은 회색 #E9E6E1입니다. 잉크 #121212, 보조 글자 #5C5A57, 구분선 #D3CFC9, 라벨 면 #FFFFFF를 씁니다.
  - 강조색은 싱글렛 사이드 테이프의 주황 #FF4A12 하나뿐입니다. 숫자 강조, 슬라이더, 핫스팟, 현재 STEP에만 칠합니다.
  - S1과 S5만 #0E0E0E 배경으로 바꿔 리듬을 줍니다. 다크 모드는 만들지 않습니다.
- **스펙 라벨.** 사이트에서 유일하게 반복하는 부품입니다.
  - 위계는 굵은 줄 8px(머리), 4px(그룹), 1px(행)으로만 만들고, 그림자와 둥근 모서리는 쓰지 않습니다.
  - 크기는 큰판(S6, S8)과 행 단위(S2) 두 가지입니다.
- **Pretendard 위계.** Pretendard Variable 하나를 woff2로 저장소에 두고, 모든 숫자에 tabular-nums를 씁니다.

  | 요소 | 굵기/크기 | 모바일 | 비고 |
  |---|---|---|---|
  | 장면 숫자 | 800 / 160px | 88px | 자간 −0.03em |
  | 단위 | 500 | 같은 비율 | 숫자 크기의 0.35배 |
  | 장면 제목 | 700 / 56px | 30px | 줄간 1.25, word-break keep-all |
  | 본문 | 500 / 20px | 17px | |
  | 라벨, 규격 | 500 / 14px | 14px | 회색 |
  | 고지문 | 400 / 13px | 13px | |

  영문 대문자 라벨은 없앱니다. 영문은 지표 약어(GSM, CFM, MVTR, RET, CLO)와 규격 번호에만 남깁니다.
- **그리드.** 12칼럼, 최대 폭 1280px, 거터 24px, 좌우 여백 48px(모바일 16px)입니다. 장면 틀은 두 가지만 씁니다. 왼쪽 5칸 주장과 오른쪽 7칸 시각물을 나누는 틀, 그리고 전체 폭 숫자 틀입니다.
- **사진 톤.** 모든 사진을 스튜디오 한 톤으로 묶습니다.
  - 따뜻한 밝은 회색 무지 배경, 왼쪽 위 대형 소프트박스, 옅은 바닥 그림자를 씁니다.
  - 무광 검정 원단에 주황 포인트는 하나만 두고, 사람과 로고와 글자는 넣지 않습니다.
  - S5는 배경만 어둡게 바꾸고 조명과 그레이딩은 그대로 둡니다.
  - 원단은 지그재그로 재단한 지름 8 cm 원형 시험편으로 통일합니다. 시험이라는 주제가 사진에서도 이어집니다.
- **모션.**
  - 장면 제목은 줄당 400ms, 80ms 간격으로 12px 아래에서 올라옵니다.
  - 팝업은 scale 0.95에서 1로 커지며 fade 200ms ease-out으로 열리고, 닫을 때는 150ms ease-in입니다.
  - 바텀시트는 300ms로 열리고 250ms로 닫힙니다. 숫자 끄기 전환은 200ms 크로스페이드입니다.
  - transform과 opacity만 움직입니다. prefers-reduced-motion에서는 이동 없이 150ms fade만 남깁니다.

## 6. 기술 선택

빌드 없는 정적 HTML, CSS, 바닐라 JS로 다시 만들고 Vercel에 그대로 배포합니다. Astryx도 검토했지만 쓰지 않습니다. 추천 템플릿인 table-comparison은 이번에 줄이려는 표 중심 화면이고, 장면 9개와 작은 상호작용 다섯 개 때문에 React, StyleX, Vite 빌드를 4일 안에 새로 세우기에는 비용이 큽니다.

코드 위치는 이렇게 나눕니다.

| 역할 | 파일 | 내용 |
|---|---|---|
| 숫자와 문구 | data.js | PRODUCTS, METRICS, STEPS, BRANDS |
| 판단 | logic.js (DOM 없음) | coversTemp, recommend |
| 표현과 연결 | app.js | 상태 객체 `state = {scene, numbersOff, sheet, temp, step}`와 setState 하나 |
| 토큰 | styles.css | :root |

권장 기온은 템포런 강도로 달릴 때를 기준으로 정합니다. S7 막대와 추천 결과를 같은 PRODUCTS.temp에서 뽑아, 지금 tempNote와 recommend()가 서로 다른 결과를 내는 문제를 없앱니다. 다음 가정값은 근거가 약해서 화면에서 빼고 발표 노트로 옮깁니다.

- 레이스 강도 보정 +9°C
- 강수 보정 −3°C
- 풍속 체감 산식
- 일반 품목 CLO 합산
